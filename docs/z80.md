# The CPU: `z80`

A Zilog Z80 (NMOS), exact to the machine cycle and to every flag bit, on any bus. It runs every opcode of its
seven tables (unprefixed, CB, ED, DD, FD, DDCB, FDCB: 1,792 in all, documented or not), keeps the internal
registers that show through the flags (MEMPTR and Q), counts R as the chip does, takes interrupts (IM 0, 1, 2
and NMI) with their exact timing, HALTs as the chip halts, and drives its bus one machine cycle at a time so that
the machine around it (a Spectrum's ULA) can insert its wait states exactly where the real ones fall. A
disassembler comes with it.

It passes, completely, every oracle there is for it: the FUSE emulator's core tests (1,356 of 1,356, bus event
by bus event), all 1,604,000 SingleStepTests (T-state by T-state, pin by pin), Frank Cringle's ZEXDOC and
ZEXALL (67 of 67 groups each), and Patrik Rak's z80test, whose every expected value was measured on a Zilog chip
(all 156 tests of each variant: all registers and flags, Q through CCF, MEMPTR through BIT). It runs about 77
million instructions a second, some 175 times a real Z80.

## How the machine drives it

```rust
use z80::{Bus, Cpu, Regs};

pub trait Bus {
    fn fetch(&mut self, addr: u16, ir: u16, t: &mut u32) -> u8;  // M1, 4 T: opcode at addr, then refresh at ir
    fn read(&mut self, addr: u16, t: &mut u32) -> u8;            // 3 T
    fn write(&mut self, addr: u16, value: u8, t: &mut u32);      // 3 T
    fn internal(&mut self, addr: u16, n: u32, t: &mut u32);      // n T, addr on the bus, no MREQ/IORQ
    fn port_in(&mut self, port: u16, t: &mut u32) -> u8;         // 4 T (one automatic wait state)
    fn port_out(&mut self, port: u16, value: u8, t: &mut u32);   // 4 T
    fn int_ack(&mut self, t: &mut u32) -> u8;                    // 6 T: INTA M1 with 2 wait states; the data bus
}

pub struct Cpu {
    pub regs: Regs,                                                          // the whole state, plain fields
    // (and two values that live only within a step)
}

impl Cpu {
    pub fn new() -> Cpu;                                                     // power-on
    pub fn reset(&mut self);                                                 // the RESET line
    pub fn step(&mut self, bus: &mut impl Bus, t: &mut u32);                 // one instruction / HALT cycle / prefix
    pub fn interrupt(&mut self, bus: &mut impl Bus, t: &mut u32) -> bool;    // INT held: taken?
    pub fn nmi(&mut self, bus: &mut impl Bus, t: &mut u32) -> bool;          // NMI edge: taken?
    pub fn accepts_interrupt(&self) -> bool;                                 // would `interrupt` take one now?
}

pub fn z80::disasm::disassemble(read: impl Fn(u16) -> u8, addr: u16) -> z80::disasm::Instruction;
// Instruction { len: u8, text: String, undocumented: bool }
```

The trait is the one `docs/architecture.md` sketches, unchanged in shape; what each method means is pinned down
here and in the crate. Each method is one machine cycle (or, for `internal`, some T-states inside one) that
starts at `*t` and must leave `*t` past its end, wait states included. The CPU calls them in the chip's order,
with `*t` at each cycle's first T-state, and never adds to `t` itself.

- `fetch`'s `ir` is the refresh address of T3–T4: I in the high byte, R as it was before this fetch counted it.
  It is there for what the refresh does on a machine (the 48K's "snow" when I points at contended memory); the
  CPU also uses `fetch` for the opcode reads it throws away (each cycle of HALT, and the NMI response).
- `internal` is the chip working inside with an address left on the bus: after an M1 cycle (INC BC's 2, ADD
  HL,rr's 7, PUSH's 1) it is the refresh address the fetch put out; after a read or write it is that cycle's
  address (INC (HL)'s 1 at HL, LDIR's 2 + 5 at DE, JR's 5 at the displacement). A Spectrum's ULA looks at each
  of those T-states on its own, so `n` is to be contended T-state by T-state, as FUSE does.
- `int_ack` returns the byte the interrupting device drives, which on a Spectrum is FFh (nothing drives it).
  The CPU follows it with one `internal` T-state at the refresh address, then the pushes.

The machine calls the CPU at each instruction boundary, offering an NMI if one is pending, else INT if the line
is held, then stepping:

```rust
while t < frame_len {
    if nmi_pending && cpu.nmi(&mut bus, &mut t) {
        nmi_pending = false;
    } else if int_held_at(t) {
        cpu.interrupt(&mut bus, &mut t);
    }
    cpu.step(&mut bus, &mut t);
}
```

- **INT** is a level: offer it at every boundary while it is held, and the CPU takes it when it can. It refuses
  while IFF1 is clear, directly after EI, directly after a RETI/RETN that copied a set IFF2 into a clear IFF1,
  and between a DD/FD prefix and its opcode. The chip samples INT in the last T-state of an instruction; FUSE,
  whose Spectrum timings are measured against the hardware, asks whether INT is held at the boundary `t` itself
  (an interrupt is taken on the 48K if an instruction ends before T-state 32). Which T-state to ask about is the
  machine's convention to settle against its tests.
- **NMI** is an edge: it is taken at the next boundary that is not between a prefix and its opcode (EI does not
  hold it off). After `nmi` returns true, `step` before offering another: the chip does not accept a second NMI
  during its NMI response (Manuel Sainz de Baranda y Goñi, 2022), so an edge that arrives then is lost.
- A **DD or FD prefix is a step of its own**: one M1 cycle, 4 T-states, R counted, after which `regs.prefix` is
  DDh or FDh and the next step runs the opcode it modifies. No interrupt or NMI is accepted in between (Sean Young
  §5.5; redcode's Z80 library and Andre Weissflog's cycle-stepped core, both checked against the transistor-level
  Visual Z80). Stepping prefix by prefix keeps every call bounded: memory full of DDs runs as the chip runs it,
  uninterruptible, but never inside one call. A debugger that steps "an instruction" steps until `prefix` is 0.
- `Regs` is everything: a snapshot or a rewind point is a copy of it, and putting it back resumes the CPU exactly,
  in the middle of a HALT or between a prefix and its opcode included.

### `Regs`

| field | what |
|---|---|
| `a f b c d e h l` | the main registers, as bytes; `af() bc() de() hl()` and `set_*` as pairs |
| `af_ bc_ de_ hl_` | the alternate set, as pairs |
| `ix iy sp pc` | |
| `i r` | R's low 7 bits count M1 cycles; bit 7 changes only by LD R,A |
| `iff1 iff2 im` | |
| `memptr` | MEMPTR (WZ) |
| `q` | Q: F if the last instruction set the flags, else 0 |
| `halted` | HALT executed; PC is past it |
| `int_blocked` | no INT at this boundary (after EI, or a RETN/RETI that enabled interrupts) |
| `prefix` | 0, DDh or FDh: a prefix is waiting for its opcode |
| `ld_a_ir` | the last instruction was LD A,I or LD A,R (an INT taken now clears P/V) |

`Cpu::new()` is power-on: PC, I, R 0, interrupts off, IM 0, everything else FFFF (Goran Devic measured FFFF,
with F sometimes FD; Sean Young recommends FFFF). `reset()` is the RESET line: PC, I, R 0, IFF1 = IFF2 = 0, IM 0,
out of HALT; everything else is kept (Devic: only PC, IR and the flip-flops are cleared). Q is cleared.

## What it does, and where each behaviour comes from

### The opcodes

All of the unprefixed, CB, ED, DD, FD, DDCB and FDCB tables, with the undocumented ones as the chip runs them:

- **SLL** (CB 30–37): shifts left and sets bit 0.
- **IXH, IXL, IYH, IYL**: under DD/FD, H and L are the index register's halves — except in an instruction that
  also has (IX+d), where they are the real H and L (LD H,(IX+d), LD (IX+d),L).
- **DDCB/FDCB copies** (low 3 bits not 6): the rotate, shift, RES or SET is done to (IX+d) and the result is also
  written to B, C, D, E, H, L or A (the real H and L). The BIT forms ignore the register field.
- **ED**: NEG has seven duplicates (ED 4C, 54, …, 7C); RETN has six (ED 55, 5D, 65, 6D, 75, 7D; ED 4D is RETI;
  all of them copy IFF2 into IFF1); IM has duplicates, and ED 4E and 6E select the undefined mode that acts as
  IM 0. ED 70 is IN F,(C) (flags only), ED 71 is OUT (C),0 (0 on NMOS chips). (ED 63 and 6B, the long forms
  of LD (nn),HL and LD HL,(nn), are documented, as the HL case of LD (nn),dd.) Every other ED opcode (00–3F,
  77, 7F, 80–9F, the gaps among A0–BF, C0–FF) is an 8 T-state no-op.
- **DD/FD before an opcode that does not use H, L, HL or (HL)**, and before EX DE,HL and EXX, which ignore it: the
  prefix costs its 4 T-states and an R, clears Q, and the opcode runs as without it. Before DD, FD or ED, the
  prefix is lost. In a run of prefixes, the last counts.

Sources: Sean Young, "The Undocumented Z80 Documented" v0.91, ch. 3–4; Cristian Dinu, "Decoding Z80 Opcodes"
(the x/y/z/p/q structure of the tables, which the disassembler follows).

### Flags

Every flag of every instruction, X (bit 3) and Y (bit 5) included, as Young's chapter 4 and the tests have them:
X and Y are bits 3 and 5 of the result for most instructions, of the operand for CP, of the high byte of the
result for 16-bit arithmetic, of A + (HL) (bits 3 and 1) for LDI/LDD, of A − (HL) − H (bits 3 and 1) for CPI/CPD,
of B for the I/O block instructions. LD A,I and LD A,R copy IFF2 into P/V.

- **BIT n,(HL)** takes X and Y from MEMPTR's high byte; BIT n,(IX+d) from the high byte of IX+d.
- **SCF and CCF** take X and Y from `(Q ^ F) | A`, where Q is F if the previous instruction set the flags and
  0 if it did not (Patrik Rak, 2012, from tests on many chips; z80test). POP AF and EX AF,AF' do not count as
  setting them. A DD/FD prefix clears Q (Tony Brewer, as SingleStepTests encode it since April 2026).
- **Block instructions that repeat** (LDIR, LDDR, CPIR, CPDR, INIR, INDR, OTIR, OTDR, on an iteration that goes
  round again): during their extra 5 T-states the chip copies bits 13 and 11 of PC — the instruction's own
  address — into Y and X; for INIR/INDR/OTIR/OTDR it also works P/V and H again from B: with the carry of the
  transfer set, P/V ^= parity((B ± 1) & 7) ^ 1 (− when the byte's bit 7 is set) and H = (B & 0Fh) == 0 (or 0Fh);
  without it, P/V ^= parity(B & 7) ^ 1. (David Banks, "Undocumented Z80 Flags", 2018.) These are the flags an
  interrupt that lands in the middle of a LDIR sees.

### MEMPTR

Set as boo_boo and Vladimir Kladov deciphered it (2006), with the I/O block instructions' repeat as rofl0r (2022)
and Manuel Sainz de Baranda y Goñi (2023) found it:

| instruction | MEMPTR |
|---|---|
| LD A,(BC) / LD A,(DE) / LD A,(nn) | address + 1 |
| LD (BC),A / LD (DE),A / LD (nn),A | A in the high byte, (address + 1) & FFh in the low |
| LD rr,(nn) / LD (nn),rr (all forms) | nn + 1 |
| ADD/ADC/SBC HL,rr (and ADD IX/IY,rr) | HL + 1, before the addition |
| JP nn, JP cc,nn, CALL nn, CALL cc,nn (taken or not) | nn |
| JR, JR cc and DJNZ when they jump; RST p | the target |
| RET, RET cc when it returns, RETI, RETN | the address popped |
| EX (SP),HL / IX / IY | the value loaded |
| IN A,(n) | (A × 256 + n) + 1 |
| OUT (n),A | A in the high byte, (n + 1) & FFh in the low |
| IN r,(C), IN F,(C), OUT (C),r, OUT (C),0 | BC + 1 |
| (IX+d) / (IY+d), any instruction | IX + d |
| RLD, RRD | HL + 1 |
| CPI / CPD | MEMPTR + 1 / − 1 |
| INI / IND | BC ± 1 before B is decremented |
| OUTI / OUTD | BC ± 1 after B is decremented |
| LDIR, CPIR, INIR, OTIR (and the D forms) when repeating | PC + 1 (the instruction's address + 1) |
| interrupt (IM 1, IM 2), NMI | the routine's address (0038h, the vector's word, 0066h) |

JP (HL), LD SP,HL, JR not taken and the rest leave it alone.

### R

R's low 7 bits count M1 cycles; bit 7 is only written by LD R,A. A prefix (CB, ED, DD, FD) is an M1 cycle; DDCB
and FDCB count 2 (their displacement and opcode are memory reads); each HALT cycle, interrupt and NMI counts 1.

### Interrupts, HALT and the EI delay

| response | cycles | T-states |
|---|---|---|
| IM 1 | INTA 6, internal 1 at IR, write PCH, write PCL; to 0038h | 13 |
| IM 2 | INTA 6, internal 1, write PCH, write PCL, read (I × 256 + byte), read + 1 | 19 |
| IM 0 | INTA 6 in place of the opcode fetch, then that opcode: FFh is RST 38h | 13 |
| NMI | opcode fetch at PC (discarded) 4, internal 1, write PCH, write PCL; to 0066h | 11 |

Each response counts R once and clears Q; INT clears IFF1 and IFF2; NMI clears IFF1 only, IFF2 keeping its value
for RETN to restore (Young §5.3, who checked that a second NMI does not overwrite it). The NMI response is 5
T-states before its pushes, not the 4 some Zilog documents draw (Goran Devic's measurements; Visual Z80). In IM 2
the vector byte is used whole: bit 0 is not ignored (Young). Sources for the cycle counts: Zilog's Z80 CPU User
Manual (interrupt response timing), Young ch. 5, redcode's interrupt notes, FUSE's z80_interrupt.

- **EI**: no INT is accepted at the boundary right after it, so EI; RETI returns before the next interrupt (Zilog;
  Young §5.5). Each EI sets the hold again, so EI; EI; EI holds INT off throughout.
- **RETI/RETN** copy IFF2 into IFF1 during the next opcode fetch, so when that enables interrupts (after an NMI),
  INT is first accepted an instruction later (Andre Weissflog, 2021; Manuel Sainz de Baranda y Goñi, 2022).
- **LD A,I / LD A,R and INT**: on the NMOS Z80, an interrupt accepted right after one of them clears P/V, the
  acknowledge having cleared IFF2 while the instruction was copying it (Zilog's Z80 Family Data Book, pp. 412–413;
  Ivan Roshchin, 1998). Not for NMI, which does not clear IFF2.
- **HALT**: the HALT is fetched and PC moves past it, as for any instruction; then, until an interrupt or NMI,
  each step is a 4 T-state M1 cycle at PC — the opcode after the HALT, read and discarded — counting R. The
  interrupt pushes that PC. (Tony Brewer, "Z80 Special Reset", 2014; confirmed on hardware by Mark Woodmass's
  HALT2INT test, 2021. Young's "PC stays at the HALT" is how it looks from outside.) On a Spectrum the fetches
  are contended like any other when PC is in contended memory.

## Disassembler

`z80::disasm::disassemble(read, addr)` gives the instruction at `addr`: its length (1–4), its text in Zilog's
mnemonics (`LD A,(IX+$05)`, `JR NZ,$8012` with the target computed, `RST $38`), and whether it is undocumented.
Undocumented instructions are written as usually known (`SLL B`, `LD IXH,B`, `IN F,(C)`, `OUT (C),0`, `RLC
(IX+$05),B` for the DDCB copies). An instruction is what one `step` runs, so a prefix that modifies nothing is a
1-byte `NOP` marked undocumented, as is an undefined ED opcode (2 bytes). All 1,792 entries of the seven tables
(text, length and the undocumented mark) were compared once, in review, with a disassembler written separately
from the opcode map, and agreed; the kept tests check every length against the CPU, and a sample of texts.

## How it is tested

`nerd test z80` (under ten seconds) and `nerd test z80-suites` (about a minute and a half). The fixtures are fetched
by `scripts/fixture` and pinned by hash; a suite whose fixture cannot be fetched reports itself skipped (on
stderr and to nerd), never passed. Each suite reports itself to nerd as a part, with its counts.

| suite | what it checks | result |
|---|---|---|
| FUSE core tests (`tests/fuse.rs`) | 1,356 tests: registers, memory, T-states, and every bus event (MC, MR, MW, PC, PR, PW) with its T-state | 1,356 of 1,356 |
| SingleStepTests sample (`tests/singlestep.rs`) | the first 25 of each of the 1,604 files | 40,100 of 40,100 |
| SingleStepTests, all (z80-suites) | 1,604,000 tests: state, memory, I/O, and the bus T-state by T-state | 1,604,000 of 1,604,000 |
| ZEXDOC (z80-suites, `tests/zex.rs`) | 67 groups, documented flags | 67 of 67 OK |
| ZEXALL (z80-suites) | 67 groups, all flags | 67 of 67 OK |
| z80test full, ccf, memptr (`tests/z80test.rs`) | 156 tests each, CRCs measured on a Zilog Z80: all registers and flags; X and Y of a CCF after each instruction (Q); of a BIT 0,(HL) after each (MEMPTR) | 156 of 156 each |
| z80test doc, flags, docflags (z80-suites) | the same as z80full with less compared, to tell what a z80full failure is | 156 of 156 each |
| behaviour (`tests/behaviour.rs`) | 23 tests: IM 0/1/2 and NMI cycle by cycle, EI, EI; HALT, IM 2 and IM 0 out of HALT, prefixes, RETN after an NMI with interrupts on and off, LD A,I and LD A,R against INT and NMI, an interrupt clearing Q, a LDIR interrupted and resumed, HALT, R, power-on and RESET; that `Regs` is the whole state (a CPU rebuilt from a copy at any boundary of random programs, interrupts and NMIs offered at random, does exactly what the original does); the disassembler's length for every opcode of every table against the CPU, and that every prefix it calls a lone NOP changes nothing | 23 of 23 |
| unit (`src/alu.rs`, `src/disasm.rs`) | flag tables, ALU cases, disassembly of documented and undocumented instructions | 5 of 5 |

**FUSE** (Philip Kendall and others; z80/tests in the fuse-emulator repository, commit 43f8878). The harness is
coretest.c's as a `Bus`: memory DE AD BE EF repeated, port reads giving the port's high byte, the contention
points printed as coretest prints them, whole instructions run until the test's T-state count. Four things in
FUSE's expectations predate later findings, and are compared as the chip does them: FUSE keeps PC at a HALT
(the chip moves past it); it prints IR after R's increment for an M1 cycle's extra T-states (the chip keeps the
refresh address it put out, one lower in R; only the low byte differs, which no contention looks at); it does
not perform an untaken JR cc / DJNZ's displacement read (no MR event; the chip reads it); and five of its tests
stop in a repeating CPDR, INIR, INDR, OTIR or OTDR whose F or MEMPTR it has as before Banks's findings. For
those five the expected values are stated in the test, with the arithmetic (CPDR at 7A45h: F A7h → AFh; INIR at
0: F 0Ch → 00h; OTIR and OTDR at 0: F 17h → 03h; INIR, INDR, OTIR, OTDR: MEMPTR = PC + 1 = 0001h). The comparator
allows the IR difference only on an internal T-state at the refresh address of the M1 cycle before it, and the
missing read only right after the opcode fetch of a JR cc or DJNZ that does not jump: every other event must be
FUSE's exactly, address and T-state.

**SingleStepTests/z80** (github.com/SingleStepTests/z80, MIT; generated from a corrected port of the Ares core,
validated in its CI against redcode's Z80 library; commit ebe1875, April 2026, which adds Brewer's finding that a
prefix clears Q). Each test's state, including wz, q, iff1/2, im, r, ei and p, is loaded, one instruction run
(its prefixes are steps), and everything compared: registers, memory, the port transactions, and the bus T-state
by T-state. Our cycles are laid out in the tests' "simplified" form (MREQ with RD/WR in one T-state of a memory
cycle, IORQ in the third of an I/O cycle) and compared pin for pin, so the order, length and address of every
cycle — internal ones included — is checked. Two fields are mapped: `ei` is our `int_blocked`, except that a
RETN/RETI enabling interrupts sets that too (see above), and `p` is our `ld_a_ir`.

**ZEXDOC and ZEXALL** (Frank D. Cringle, 1994, GPL; the binaries from yaze-ag 2.51.3, as github.com/agn453/ZEXALL
keeps them) on a minimal CP/M: the program at 0100h, BDOS functions 2 and 9 answered at 0005h, 0000h ending it.
Each runs 5,772,433,468 instructions, 46,734,975,782 T-states, and every one of its 67 groups printed OK.

**z80test** (Patrik Rak, 2012–2023, MIT; release 1.2a's tapes, github.com/raxoft/z80test) is the one oracle here
that is not another emulator: each of its tests runs an instruction over many operands and compares a CRC of the
results with one taken on a 48K Spectrum with a Zilog Z80. The programs print through the ROM's RST 10h and open
a channel at 1601h; the harness answers those two calls itself, as zex.rs answers the BDOS, and needs nothing
else of a Spectrum: RAM above 4000h, writes below it lost, port FEh reading BFh (as with no key pressed and MIC
low, which the IN tests check first) and other ports FFh. Each variant prints 156 OKs; the four other makers'
SCF/CCF variants are skipped, as they run only when Zilog's fails. z80memptr sees only MEMPTR's bits 13 and 11,
after a fixed set of operands, so it catches little that SingleStepTests would not (Rak says as much).

That the suites can fail was checked by breaking the CPU on purpose: LD SP,HL one T-state short failed FUSE's
f9/ddf9/fdf9; CPL losing X failed SingleStepTests' 2F, DD 2F and FD 2F; EX (SP),HL's internal T-state moved from
SP+1 to SP fails FUSE's e3, dde3 and fde3 and 75 SingleStepTests (FUSE's comparator first allowed the IR
difference on every internal T-state, and passed it: an address one higher in its low 7 bits looked like FUSE's
R + 1); SCF taking X and Y from F | A whatever Q was failed z80test's "CCF+SCF" in z80full and z80flags (z80ccf
did not see it: the CCF after the SCF takes X and Y from A alone, as the SCF set the flags); a Q kept outside
`Regs` failed the behaviour test that rebuilds the CPU from its registers.

## Speed

Measured, never judged by a test (the machine is shared): on this machine (Intel Core i7-14700, its cores
reported at up to 2.1 GHz), with a plain RAM bus, built as the tests build (`opt-level = 2`):

| run | instructions/s | × a 3.5 MHz Z80 |
|---|---|---|
| ZEXDOC whole, 5.77 billion instructions | 77 million | 178 |
| ZEXDOC's first 200 million (the `speed` part of the default layer) | 76–77 million | 175–177 |
| the same, `--release` (opt-level 3, fat LTO) | 88 million | 203 |

Measured again in review (October 2026, the machine shared with other work): 62–76 million at `opt-level = 2`,
88 million in release.

Decoding is a `match` per table with no allocation; nothing on the heap is touched per step. Making each opcode's
register fields compile-time constants (one instantiation per opcode) was tried and measured: no difference, so
the simpler decoder stayed.

## Known gaps

- **CMOS Z80s and clones** are not modelled: the Spectrum's are NMOS. (A CMOS chip writes FFh for OUT (C),0,
  takes SCF/CCF's X and Y from A alone, and has no LD A,I bug; NEC's NMOS µPD780 differs in SCF/CCF too.)
- **IM 0 with a multi-byte instruction on the bus**: the first byte is executed as fetched; further bytes are read
  from memory at PC (moving PC), where the chip reads them from the device in read cycles without moving PC, and
  prefixes would take further acknowledge cycles. Exact for any single-byte instruction (every RST, which is what
  hardware puts there, and FFh on a Spectrum).
- **The second-NMI rejection** is left to the machine's loop (step after an accepted NMI), as documented above.
- **The special RESET** (Brewer), BUSREQ/BUSACK and the WAIT line as a pin are not modelled; wait states are
  whatever the bus adds to `t`.
- **`int_ack` is given no address.** PC is on the address bus during the acknowledge; on a Spectrum INT comes at
  the start of the frame, far from any contended T-state, so nothing is lost there.
